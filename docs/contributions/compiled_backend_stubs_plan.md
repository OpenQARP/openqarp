## Why

`qarpx` ships no type information, so every `qx.` expression in `qarp` is `Any`.  `mypy.ini`
silences the missing module (`ignore_missing_imports` for `qarpx`), and the CI mypy job passes
while checking nothing that crosses the bindings: 558 `qx.` references in 63 `qarp` modules,
and 146 test modules importing `qarpx`.

Measured on `2167d69` with a stub generated by nanobind's `stubgen` (nanobind 3.0.1, the
CMake pin): mypy reports 228 errors in 72 files, against none today.  Twenty are in the
generated stub itself.  The rest include bugs that run today:

- `qarp/_program.py` reads `node.n_controls` on a `qx.ControlledBlock`.  A raw
  `qx.ControlledBlock` has `num_controls` and no `n_controls`, so planning one raises
  `AttributeError`.
- `is_built` is a method on a raw `qx.Block` and a property on the Python blocks.  mypy
  flags five sites that read it without calling it (`truthy-function`): `_estimator.py`,
  `haar_random_block.py`, `grover.py`, `amplitude_estimation.py` and
  `amplitude_amplification.py`.  The #13 review found `_estimator.py` and two more that
  mypy cannot see, `cutting_primitive.py` and `_circuit_adapter.py` (`to_do.md`,
  *`is_built` is a method on a raw `qx.Block`*).
- `Block.build()` returns `None` in C++ and `self` on the Python blocks; 40
  `func-returns-value` errors use the Python return value.  Which of these can receive a raw
  block is triaged in Phase 2.

The stubs also cover what a user sees: `import qarpx as qx` in an editor shows no
signatures today.

`mypy.ini` names this work as the precondition for its empty `[mypy]` section.  Its figure,
156 errors in 49 files, is stale; the measurement above replaces it.  Enabling
`check_untyped_defs` with the stubs in place reports 2196 errors in 274 files: 344 in 71
`qarp/` files and 1832 in 202 test files.  Test bodies run on every CI pass, so a wrong call
there fails anyway; library branches the tests miss are checked by nothing.  This plan turns
the flag on for `qarp/`; `tests/` follows in its own plan.

## Design

**Generation.**  `nanobind.stubgen` writes the stub from the built module, with private
members (`-P`), since `qarp` calls underscored bindings such as `_local_commands_digest`
and `_permutation_table`.  `scripts/generate_stubs.py` runs it against the installed
`qarpx` and writes `cpp/libqarpx/python/qarpx.pyi`.  The generator is the `nanobind`
Python package pinned in `[dev]` to the version CMake fetches; a test keeps the two pins
equal, since stubgen's output changes between nanobind releases.

**The stub is committed.**  A binding change then shows its type change in the same diff,
and the stub can be reviewed.  A pytest test regenerates the stub into a temporary directory
and compares it with the committed file, so a binding edit without a regenerated stub fails
in every environment that runs the suite, CI included.  The stub is excluded from ruff:
it is generated, and the drift test guards it.

**Precision lives in the bindings.**  Where the stub is wrong or vague, the binding is fixed
so that stubgen emits the right type: argument names where it emits `arg0`, `nb::sig` where
an `nb::object` or `nb::handle` parameter has a precise type, and the parameter type that
`nb::implicitly_convertible<double, Param>` and `<int, Param>` accept (today the stub
says `Param` only, so `rz(0, 0.5)` is a type error).  A pattern file is used only for what
nanobind cannot express from C++, and every pattern says why.  The stub's own 20 errors
(`__iadd__`/`__add__`, `__eq__` against `object`, `__hash__ = None`) are fixed the same way.
Changing argument names and signatures is a binding change, so `QARPX_ABI_VERSION` and
`EXPECTED_QARPX_ABI` move from 14 to 15 together (§15).

**Distribution.**  PEP 561 does not cover a stub beside a single-module extension: a
`qarpx.pyi` next to `qarpx.so` in site-packages is not read by mypy (checked: `reveal_type`
gives `Any`).  A `qarpx-stubs` package is (checked: `builtins.int`).  CMake installs the
committed stub as `qarpx-stubs/__init__.pyi` in the `python` component, so the wheel and an
editable install both carry it, and `mypy.ini` drops its `qarpx` sections.  A wheel-job step
checks that mypy resolves a `qarpx` type from the installed wheel.

**The Python blocks.**  `_attach_mixin` copies `_BlockMixin` onto each concrete class at
runtime, so mypy sees `SimpleBlock` as a bare `qx.SimpleBlock` once `qx` is typed: 17
`"Block" has no attribute "symbols"` and most of the other `attr-defined` errors.  Under
`TYPE_CHECKING` each concrete class lists `_BlockMixin` as a base, so mypy sees the methods
`_attach_mixin` copies; the runtime class is unchanged.  Where a Python override disagrees
with its C++ base (`build` returning `self`, `is_built` as a property), the override's type
is the one `qarp` relies on, and the binding moves to match when the C++ side can
(`is_built` becomes `def_prop_ro`).

**Library strictness.**  `mypy.ini` gains `[mypy-qarp.*]` with `check_untyped_defs = True`,
so unannotated function bodies in the library are checked; `[mypy]` stays empty, and
`tests/` keeps today's setting.  Of the 184 `qarp/` errors the flag adds, the ones the
mixin, `Param | float` and `is_built` fixes do not clear are about 160 in 28 files.  Two
patterns make up about 100 of them: callbacks carrying iteration state as function
attributes (`callback.previous_energy`, `.iter`), and `Optional` values used without a
`None` check.  Each pattern is fixed one way across its files.  A few look like bugs
(`adapt_vqd.py` passes a list of lists to `Engine.build`; `montecarlo.py` calls `.items()`
on a value typed `complex`); each confirmed one gets a regression test.

**Conventions.**  §15's ABI bullet gains one rule: a commit that changes a binding also
regenerates `qarpx.pyi`.  No other convention changes.

**No example.**  The stubs change no runtime behaviour, so there is no notebook to run.

### Decisions

- **The `is_built` entry from `to_do.md` is folded in.**  The stubs surface it as
  `truthy-function` errors, it needs the same ABI bump, and leaving it would type a method
  that every Python block overrides with a property.  *(2026-10-15)*
- **The stub ships in the wheel.**  Users get signatures in their editors; the price is a
  public typing surface for `qarpx` that changes with each ABI bump.  *(2026-10-15)*
- **Based on `develop`.**  #13 changes no C++, PRs land squashed, and a branch based on #13
  would carry its diff in this PR until #13 lands.  #13's own `qx` calls are type-checked
  once it lands.  *(2026-10-15)*
- **Private members are in the stub** (`-P`).  `qarp` calls ten underscored bindings (the
  command digests, `_permutation_table`, `_local_unitary`, the thread-budget functions,
  `Block._copy_base_state_from`), and those are the calls most worth checking.  The
  underscore keeps them private; `dir(qx)` already lists them.  *(2026-10-15)*

- **`check_untyped_defs` is on for `qarp/` in this plan; `tests/` gets its own.**  The
  library is where unchecked bodies hide bugs; the tests' 1832 errors would touch nearly
  every test file and are parked in `to_do.md`, for after the layout move.  *(2026-10-15)*

## API sketch

```text
# Wheel and editable install
site-packages/qarpx.cpython-*.so
site-packages/qarpx-stubs/__init__.pyi      # from cpp/libqarpx/python/qarpx.pyi

# Regenerate after a binding change
python scripts/generate_stubs.py            # writes cpp/libqarpx/python/qarpx.pyi
```

```python
# qarpx.pyi (excerpts, as the fixed bindings make stubgen emit them)
__abi_version__: int = 15

class Block:
    @property
    def is_built(self) -> bool: ...
    def rz(self, qubit: int, theta: Param | float) -> Block: ...

class ControlledBlock(Block):
    def __init__(self, inner: Block, num_controls: int, ctrl_state: Sequence[bool],
                 name: str = "Controlled") -> None: ...
    @property
    def num_controls(self) -> int: ...
```

```python
# qarp/blocks/_block.py
if TYPE_CHECKING:
    class SimpleBlock(_BlockMixin, qx.SimpleBlock): ...
else:
    @_attach_mixin
    class SimpleBlock(qx.SimpleBlock): ...
```

The exact spelling of the `TYPE_CHECKING` split is settled in Phase 2.  Only one class body is
written; the split is on the bases.

## Test plan

| Test | Oracle | Location |
|---|---|---|
| The committed stub equals a fresh stubgen run on the installed module | the built module, read by the pinned generator | `tests/test_stubs.py` |
| The `nanobind` pin in `[dev]` equals the CMake `GIT_TAG` | `cpp/libqarpx/CMakeLists.txt` | `tests/test_stubs.py` |
| mypy accepts a table of `qx` calls exactly when the runtime does (`rz(0, 0.5)`, `rz(0, "t")`, `ControlledBlock(b, 1, 1)`, keyword arguments by name, …) | the runtime: each call run, `TypeError` or not | `tests/test_stubs.py` |
| `qarp/` type-checks with the stub and `check_untyped_defs`; `tests/` with the stub | mypy over the code | CI `mypy` job |
| mypy resolves a `qarpx` type from the installed wheel | the binding's declared C++ type (`int` for `n_qubits`) | `wheels.yml` step |
| `is_built` is `False` on a fresh raw block and `True` after `build()` | the build lifecycle | `tests/test_blocks/test_block.py` |
| Planning a raw `qx.ControlledBlock` of an X gives CX | the analytic CX matrix | `tests/test_blocks/test_structure.py` |
| `ResourceEstimator.estimate`, `CuttingPrimitive` and `CircuitAdapter` accept an unbuilt raw block | gate counts and an expectation computed by hand for the circuit written | beside each site |
| Each further bug Phase 2 finds | an analytic or hand-computed value, named in the PR | beside each site |
