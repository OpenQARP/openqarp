## Why

`docs/contributions/README.md` reserves the 0.2 cycle for the layout so that
paths break once: the `src/` source root and the `cpp/` flattening.  The
flattening goes one step further here: the C++ project moves under `src/` as
`qarpx`, so both import names sit on directories of their name.  The two
other 0.2 gates, lazy circuits and the compiled-backend stubs, have landed;
this is the last.

Today `import qarp` from the repository root resolves the source tree whether
or not the package is installed, which is how a stale editable install goes
unnoticed until the ABI stamp catches it, and why `tests/`, `benchmarks/` and
`scripts/` are importable by accident rather than by decision.  A `src/` root
makes the installed package the only importable one.  `cpp/libqarpx/` is one
directory holding one project; the extra level names nothing and costs every
path in the build, the workflows, the scripts and the docs a segment.

## Design

**Layout.**  `src/qarp/` is the package, `src/qarpx/` the CMake project
(`CMakeLists.txt`, `include/qarpx/`, `src/`, `python/`, `tests/`,
`third_party/`), its inner structure unchanged.  `cpp/` is gone.  No file
changes content in the move itself; every edit is a path.  `tests/`,
`benchmarks/`, `scripts/`, `examples/`, `docs/` stay.

`src/qarpx/` is a directory named like the compiled module and has no
`__init__.py`.  The editable install's `.pth` puts `src/` on `sys.path`
(scikit-build-core registers the parent of `wheel.packages`), so with the
compiled module missing, `import qarpx` would yield an empty namespace
package instead of an `ImportError`.  The redirect finder serves the
compiled module first whenever it exists; `qarp/__init__.py` refuses a
`qarpx` without `__file__` with the same "not importable" message, and a
subprocess test pins it.  mypy and pyright must keep resolving `qarpx`
through the stub at `src/qarpx/python/qarpx.pyi`, which `mypy_path` and
`stubPath` name and which they search before source roots; the mypy run is
the check.

**Build.**  `[tool.scikit-build]` sets `cmake.source-dir = "src/qarpx"` and
`wheel.packages = ["src/qarp"]`; `build-dir`, the install components and the
sdist rules keep their meaning with the new prefixes.  The compiled module
still installs to the wheel root (`import qarpx`) and the stub to
`qarpx-stubs/`.  `CMAKE_SOURCE_DIR`, baked into the module as
`QARPX_SOURCE_DIR`, becomes `<checkout>/src/qarpx`; `_abi.py` derives the
expected tree as `Path(__file__).resolve().parents[1] / "qarpx"`
(`src/qarp/_abi.py` → `src/qarp`, `src`), and a wheel install finds no
`qarpx` directory beside its `qarp`, so the source-dir check stays off there.

**Import path.**  The editable install maps `qarp` to `src/qarp` and puts
`src/` on `sys.path`; the repository root is no longer there by virtue of the
install.  `scripts/bootstrap_qarpx.py`'s `.pth` names `src/` too.  pytest
puts it there (the `tests/` package sits under a root with no `__init__.py`),
which is what `tests/test_benchmarks` and `tests/test_docs` rely on, and the
subprocess tests insert it explicitly already.  `docs/conf.py` keeps its
`sys.path.insert(0, "..")`, which is inert now: the root holds no package.
Autodoc imports the installed package; under an editable install `src/` is
on the path too, and the compiled module is served ahead of the `src/qarpx/`
directory as described above.

**§15 edits, deliberate.**  The path pointers (`cpp/libqarpx/python/bindings.cpp`,
`cpp/libqarpx/python/qarpx.pyi`, `qarp/_abi.py`, `qarp/<pkg>/__init__.py`,
`qarp/__init__.py`) move with the files, and the sentence "An editable install
puts the repository root on `sys.path`, so every tree is importable" becomes
"pytest puts the repository root on `sys.path`, so every tree is importable
from a test", which is the true mechanism under both layouts.  The other
sections cite files (§2.3, §11, §12, §20) and are re-pathed.

**Tooling.**  mypy's `mypy_path` and pyright's `stubPath` point at
`src/qarpx/python`; the CI mypy command checks `src/qarp tests/`; ruff's exclusion
of the stub and its per-file ignore for `src/qarp/__init__.py` follow;
coverage keeps `source = ["qarp"]` (a package name) and remaps
`src/qarp` ↔ `*/site-packages/qarp`, so `relative_files` reports and
diff-cover's `git diff` paths agree on `src/qarp/...`; the `ctest` and
LAPACK jobs configure `-S src/qarpx -B src/qarpx/build-ci`; `.gitignore`
ignores `src/qarpx/build*/`.  `CODEOWNERS` re-paths its 59 `/qarp/` and
`/cpp/libqarpx/` rules; nothing else about ownership changes.

**The orphaned bindings test.**  `cpp/libqarpx/tests/python/test_mcm_bindings.py`
is run by nothing: `pytest.ini` collects `tests/` only and no workflow or
script names it.  It moves to `tests/test_bindings/` and is collected, provided
it passes on the current bindings; if it does not, the failure is reported and
the file is deleted instead, as a one-time removal.

**Decisions, settled at the sit-down (2026-11-13).**

1. Layout: `src/qarp/` and `src/qarpx/`, the C++ project's inner tree kept.
   A flat `cpp/` at the root was the first draft; both names under one root
   was preferred.  Flattening the inner `src/` too was rejected: it rewrites
   every CMake source list for no gain.
2. The bindings test moves under `tests/` and is collected.
3. Landed plans and review files keep their historical paths.
4. Ordering: this PR merges before the 0.2 release PR and before any open
   branch rebases (`improvement/circuit_cutting_shot_allocation`,
   `feature/oqtopus-integration`, `feature/pauli-engine`, `research/qmc`,
   `chore/perf-profiling`, the targets plan).  Git follows renames through a
   rebase for edited files; a file those branches *add* under `qarp/` or
   `cpp/` lands at the old path and is moved by hand.

**Who sees a change.**  Wheel users: nothing; import names, module paths and
the stub are unchanged.  Checkout users: `pip install -e .` again in every
worktree (the editable finder maps the old directory), `cmake -S src/qarpx`,
and the documented paths.  Any external text that linked `qarp/...` or
`cpp/libqarpx/...` on GitHub.

## API sketch

No Python API changes.  The surfaces that move:

```text
qarp/                         → src/qarp/
cpp/libqarpx/CMakeLists.txt   → src/qarpx/CMakeLists.txt
cpp/libqarpx/include/qarpx/   → src/qarpx/include/qarpx/
cpp/libqarpx/src/             → src/qarpx/src/
cpp/libqarpx/python/          → src/qarpx/python/     (bindings, qarpx.pyi, stubgen_patterns.txt)
cpp/libqarpx/tests/cpp/       → src/qarpx/tests/
cpp/libqarpx/tests/python/test_mcm_bindings.py → tests/test_bindings/test_mcm_bindings.py
cpp/libqarpx/third_party/     → src/qarpx/third_party/
```

```toml
[tool.scikit-build]
cmake.source-dir = "src/qarpx"
wheel.packages = ["src/qarp"]
sdist.exclude = ["src/qarpx/build/**", "**/__pycache__/**", "**/*.so", "**/*.pyd"]

[tool.coverage.paths]
source = ["src/qarp", "*/site-packages/qarp"]
```

```python
# src/qarp/_abi.py
source_tree = Path(__file__).resolve().parents[1] / "qarpx"
```

```cmake
# src/qarpx/CMakeLists.txt
add_subdirectory(tests)
```
